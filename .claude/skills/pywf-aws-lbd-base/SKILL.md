The conventions of a multi-environment AWS Lambda project generated from the pywf AWS Lambda template, which extends the pywf AWS CDK template. A generated project already follows all of them; this skill says what they are, so changes keep them.

## Version

Template **1.0.0**, the `version` in the seed repo's `pyproject.toml`. Every link points to the git tag of that version: [MacHu-GWU/cookiecutter_aws_lbd_demo-project at 1.0.0](https://github.com/MacHu-GWU/cookiecutter_aws_lbd_demo-project/tree/1.0.0). If the project in front of you differs from the linked files, the project wins; tell the user.

## Precedence

For the layout of stacks, follow `references/15-cdk-stack-enums.md`, not the multi-stack best practice of cdk_mate. For a library's API, use its own skill: `pypi-cdk_mate`, `pypi-aws_lbd_art_builder_uv` and `pypi-aws_lbd_art_builder_core` (layer and source build), `pypi-simple_aws_ssm_parameter_store` (config deploy), `pypi-boto_session_manager`, `pypi-s3pathlib`; and the `aws-cdk-cli-ref` skill for a cdk CLI option.

## References

`00` is how this skill is written. `01`–`08` are general and never mention Lambda or CDK. Then, from code to deployment: `09`–`13` the Lambda code, the devops environment, and the config in SSM (`lbd-`); `14`–`19` the CDK part (`cdk-`); `20`–`24` shipping the functions (`lbd-`). For a question, read only the file that covers it.
