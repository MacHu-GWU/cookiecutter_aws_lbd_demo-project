# CDK mise Tasks

Seed repo: [`mise_tasks.py`](https://github.com/MacHu-GWU/cookiecutter_aws_lbd_demo-project/blob/1.0.0/cookiecutter_aws_lbd_demo/cdk/mise_tasks.py), [`mise.toml`](https://github.com/MacHu-GWU/cookiecutter_aws_lbd_demo-project/blob/1.0.0/mise.toml).

---

## 1. Generated, never hand edited

`mise run cdk-gen-tasks` rewrites the block between `# <cdk-stack-tasks>` and `# </cdk-stack-tasks>` in `mise.toml` from the entries of `StackCtxEnum` (`15-cdk-stack-enums.md`) and the workload members of `EnvNameEnum` (`03-env.md`); the devops environment gets no task (`12-lbd-devops-env.md`). Rerun it after changing either. A unit test fails while the block is stale.

---

## 2. The tasks

| Task | cdk command | Calls AWS |
| :--- | :--- | :--- |
| `cdk-synth-<env>-<x>-stack` / `-all` | `cdk synth` | no |
| `cdk-plan-<env>-<x>-stack` / `-all` | `cdk diff --method auto` | reads |
| `cdk-up-<env>-<x>-stack` / `-all` | `cdk deploy --require-approval never` | changes |
| `cdk-down-<env>-<x>-stack` / `-all` | `cdk destroy --force` | changes |

- Each task runs one plain cdk command in `cdk/`, with `ENV_NAME=<env>`. A `-stack` task selects the stack by its name with `--exclusively`; an `-all` task uses `--all` (synth needs none) and lets cdk order the stacks.
- Every task but synth passes `--profile {{env.AWS_PROFILE_FOR_<ENV>}}` (`06-boto-session.md`) and stops if the variable is unset.
- **Before the command, every task prints the CloudFormation console URL** (`config.cft_stack_url_<x>`) of each stack it acts on, then the command line.
- **Dependencies:** every task depends on `inst` and `lambda-source-build`, because the Lambda stack deploys the built source folder and cannot synthesize without it. Every `up` task also depends on `lambda-layer-check-<env>` (stop before CloudFormation if the environment cannot use its layer version) and `config-deploy-<env>` (`13-lbd-config-ssm.md`), so code and config ship together.

---

## 3. The other tasks of the block

| Task | Does | Calls AWS |
| :--- | :--- | :--- |
| `config-deploy-<env>` / `config-delete-<env>` | write / delete the config of `<env>` in SSM (`13-lbd-config-ssm.md`) | changes |
| `config-deploy-all` / `config-delete-all` | the same, for every workload environment | changes |
| `lambda-layer-check-<env>` | can `<env>` use the layer version of its config | reads |
| `cdk-gc-<env>` | `cdk gc --unstable=gc --action=print`: list unused assets in the bootstrap bucket | reads |

---

## 4. `print-cdk-stack-urls`

`mise run print-cdk-stack-urls` prints the console URL of every stack in every environment, without calling AWS.

---

## 5. The user's yes

- Run freely: `synth`, `plan`, `cdk ls`, `cdk-gen-tasks`, `print-cdk-stack-urls`, `lambda-layer-check-<env>`, `cdk-gc-<env>`.
- `up`, `down`, `config-deploy-*`, and `config-delete-*` change AWS: run them only after the user's yes, one environment per yes. `mise run int-test` invokes the deployed functions and writes test data; it needs the user's yes too. Each of these says `writes to AWS` in its description.
- To run one stack yourself, call the cdk CLI from `cdk/`: `ENV_NAME=<env> mise exec -- cdk diff <stack_name> --exclusively --profile "$AWS_PROFILE_FOR_<ENV>"`. For a cdk option, see the `aws-cdk-cli-ref` skill.
